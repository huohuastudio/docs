# 区域管理 {#region}

区域代表一个地理位置或数据中心，如「香港」「东京」「洛杉矶」。节点归属于区域，用户下单时选择区域，系统从区域内的可用节点中自动分配。

区域还用于仪表盘地图展示、官网数据中心页面等场景。

## 创建区域 {#create}

在管理面板的「区域管理」页面，点击「添加区域」按钮，填写以下信息：

| 字段 | 说明 |
|------|------|
| 展示名称 | 用户可见的区域名称，如「香港」 |
| 区域代码 | 唯一标识符（如 `hk`），用于 API 调用和内部标识 |
| 内部名称 | 管理后台使用的名称（可选），留空则使用展示名称 |
| 国家/地区 | 从内置的国家列表中搜索选择，支持中文、拼音和英文检索 |
| 城市 | 所在城市 |
| 国旗 | 选择国家后自动填充，也可手动修改 |
| 线路信息 | 网络线路描述，如「BGP」「电信」「CN2 GIA」 |
| 经纬度 | 用于仪表盘地图标点（可选） |
| 描述 | 区域的补充说明（可选） |
| 特性 | 标签形式的特性列表（可选），如「高带宽」「低延迟」「DDoS 防护」 |
| 测试 IP | 供用户测速的 IP 地址（可选） |
| 图片 | 区域展示图片（可选），用于官网等展示场景 |
| 公开展示 | 开启后该区域会出现在官网数据中心页面 |
| 状态 | 活跃、停用或维护中 |
| 排序权重 | 数字越小排越前 |

::: tip
选择国家后，系统会自动填充国旗 emoji 和区域代码（如果区域代码为空）。区域代码建议使用国家代码加城市缩写的组合，如 `hk`、`us-la`、`jp-tk`。
:::

## 区域与节点 {#region-node}

区域和节点的关系：一个区域可以包含多个节点，一个节点只能归属一个区域。

在[添加节点](./node#add-node)时，通过下拉选择器关联区域。未关联区域的节点不会参与下单自动调度。

::: warning
如果区域下没有任何在线节点，该区域关联的套餐在用户下单时会显示「售罄」。
:::

## 下单自动调度 {#auto-dispatch}

用户下单时选择的是区域而非具体节点。系统会从该区域内的可用节点中随机分配一台，自动完成实例创建。

调度逻辑：
1. 筛选区域内所有在线节点
2. 过滤掉资源不足（CPU、内存、磁盘、IP）的节点
3. 从剩余节点中随机选择一台

这样即使同一区域有多台节点，用户也无需关心具体分配到哪台。管理员只需按地理位置规划区域和节点，系统自动处理负载分散。

## 官网展示 {#public-display}

开启「公开展示」的区域会通过 CMS 接口 `GET /api/v1/public/cms/regions` 返回给前端主题渲染。展示信息包括区域名称、国旗、线路、特性标签、测试 IP 和图片等。

可以在[内容管理](./cms)的「数据中心」模块中预览公开展示的区域列表。

## 状态说明 {#status}

| 状态 | 说明 |
|------|------|
| 活跃 | 正常使用，节点可分配 |
| 停用 | 该区域暂停使用，关联节点不参与下单调度 |
| 维护中 | 临时维护，行为与停用相同 |

## 修改和删除 {#edit-delete}

- **修改区域**：修改区域信息不影响已创建的实例，仅影响后续的展示和调度
- **删除区域**：如果区域下还有关联的节点，系统会拒绝删除。请先将节点移至其他区域或移除区域关联
